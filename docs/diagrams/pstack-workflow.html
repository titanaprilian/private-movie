Multi-Tier Orchestration & Agent Workflow

End-to-end lifecycle across Operator, Orchestrator, Worker pane, and Delegated Subagents. Requirements are settled through batched grilling before poteto-mode coordinates coding and verification.

STAGE 01 · INTAKE & GRILLING

Isolation & Stress-Testing

The Operator kicks off a task with the Orchestrator agent. Instead of writing code directly in the root workspace, the orchestrator sets up an isolated worktree and opens a dedicated Herdr worker pane.

  • Worker runs pstack:grilling to stress-test requirements and build a decision tree.
  • Frontier questions (❓ Q1..Qn) are presented in one cohesive chat turn.
  • Operator or Orchestrator grants single-turn approval ("approve all recommended answers").

STAGE 02 · POTETO-MODE HUB

Specification & Delegation

Upon settling the design tree, Grilling outputs the formal execution brief (Goal, Constraints, Done Check) and transitions seamlessly into pstack:poteto-mode.

  • Worker matches the task to the appropriate playbook (Feature, Bug fix, Refactor).
  • Worker delegates coding to fresh subagents (poteto-agent, pstack:architect).
  • Follows TDD red-to-green and strictly adheres to Deep Module boundaries.

STAGE 03 · VERIFICATION & CLOSE

Audit, Ship & Reverse-Prompt

Before merge-readiness, independent audit subagents run rigorous quality gates (thermo-nuclear-review, verify, deslop, no-comments).

  • Worker confirms green gates (bun run gate:check) and pushes via ship.sh.
  • Zero-polling reverse prompt (WORK_COMPLETE) alerts the Orchestrator.
  • Orchestrator confirms merge, cleans up worktree, and closes the worker pane.
